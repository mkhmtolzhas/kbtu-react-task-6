# Решения и допущения

Журнал архитектурных решений проекта FleetDesk. Каждое решение — с причиной.

## Стек

| Решение | Почему |
| --- | --- |
| Vite 8 + React 18.3 (JSX, без TypeScript) | Требование задания; React 18 — версия курса. |
| `react-router-dom` 7, `createHashRouter` + `RouterProvider` | Hash-роутинг работает на любом статическом хостинге без rewrite-правил. Используется data-router вариант `HashRouter`, потому что только он поддерживает `<ScrollRestoration />` (сброс скролла при переходе на новую страницу и восстановление при «Назад»). |
| ESLint 9 (flat config) | `eslint-plugin-react` пока не поддерживает ESLint 10. |
| `eslint-plugin-react-hooks` 5.2 | Версии 6–7 включают правила React Compiler (например, `set-state-in-effect`), которые запрещают классический паттерн «загрузка данных в `useEffect`», изучаемый в курсе. Версия 5 даёт ровно `rules-of-hooks` и `exhaustive-deps`. |
| `eslint-plugin-react` | Правила `jsx-key` и `no-array-index-key` автоматически гарантируют стабильные keys. |
| Правило `no-restricted-properties` / `no-restricted-syntax` | Линтер запрещает `querySelector`, `getElementById`, `innerHTML` и т.п. Единственное исключение — `src/main.jsx`, где `document.getElementById('root')` нужен для монтирования приложения (это не манипуляция DOM). |
| Обычный CSS с CSS-переменными, mobile-first | Требование задания; тёмная тема через `prefers-color-scheme`. |
| `base: './'` в `vite.config.js` | Относительные пути к ассетам: сборка работает и в корне домена (Vercel/Netlify), и в подпапке (GitHub Pages `/<repo>/`). Вместе с hash-роутингом не нужен никакой серверный конфиг. |

## Язык

## Simulated API (`src/api/`)

- Своих файлов «provided simulated API» в репозитории нет — построен собственный API.
- 180 записей, генерируются детерминированно (PRNG `mulberry32` с фиксированным seed и фиксированной «датой генерации» `2026-10-15`), поэтому у всех пользователей одинаковые начальные данные.
- Хранилище — `localStorage` под ключом `fleetdesk.db`, внутри `{ version, nextId, vehicles }`. При несовпадении `version` с `SCHEMA_VERSION` база пересоздаётся из seed. Если `localStorage` недоступен (приватный режим), API работает с копией в памяти.
- Все методы возвращают Promise с задержкой 400–900 мс. Методы чтения принимают `{ signal }` и при отмене отклоняются с `DOMException('…', 'AbortError')`.
- Фильтрация, поиск, сортировка и пагинация выполняются в API-слое; ответ `{ items, total, page, pageSize }`.
- API возвращает копии объектов (`structuredClone`), чтобы UI не мог случайно мутировать «базу».
- Ошибки — класс `ApiError` со статусом (`404`, `409`, `422`, `500`) и, для ошибок валидации, полем `fieldErrors`.
- Дополнительно к обязательным методам есть `getFleetStats({ signal })` — сводка по статусам для плиток-фильтров на главной.
- Сущность `Vehicle` расширена полем `statusHistory: [{ status, changedAt }]` — история смен статуса отображается на детальной странице и пополняется методом `updateVehicleStatus`.
- Бизнес-правила в API: статус `charging` разрешён только для класса `electric`; перевести в `rented` можно только авто с уровнем топлива/заряда ≥ 15 %; номер должен быть уникальным.
- Имитация ошибок: `?simulateError=1` — каждый запрос падает с 500; дробное значение (`?simulateError=0.3`) — запрос падает с такой вероятностью. Параметр читается из `window.location.search` и из query внутри hash (`#/?simulateError=1`).
- Номера KZ: формат `123 ABC 02` (02 — код Алматы).

## Состояние и данные

- Состояние списка (поиск, фильтры, сортировка, страница, размер страницы) живёт в `VehiclesPage` и дублируется в `sessionStorage` через хук `useSessionState`. Причина: при переходе в карточку авто и возврате назад страница списка размонтируется; без сохранения пользователь терял бы фильтры и номер страницы.
- Поиск: значение input обновляется сразу (controlled), в API уходит значение после debounce 400 мс (хук `useDebouncedValue`, cleanup — `clearTimeout`).
- Сброс страницы на 1 делается в обработчиках событий вместе с изменением фильтра (одна пачка обновлений), а не эффектом.
- Пока идёт повторная загрузка списка, предыдущие результаты остаются на экране полупрозрачными (`aria-busy`), а не заменяются спиннером — это убирает «прыжки» вёрстки при пагинации. При первой загрузке показывается спиннер.
- Детальная страница: `VehicleDetailsPage` (маршрут) рендерит `<VehicleDetails key={id} />`. Смена `id` (переход на «похожее авто») пересоздаёт всё поддерево — нет «мелькания» старого авто и не нужно вручную сбрасывать состояние. Состояние калькулятора поездки (`tripMinutes`) намеренно хранится выше границы `key` и сохраняется при переходах между авто, чтобы диспетчер мог сравнивать стоимость.
- После успешной смены статуса состояние обновляется иммутабельно: `setVehicle(prev => ({ ...prev, status, statusHistory }))`.
- После создания авто — переход на его детальную страницу (`navigate('/vehicles/:id')`).
- Прокрутка вверх при смене страницы списка — `window.scrollTo` в обработчике клика. Это вызов браузерного API окна, а не изменение DOM-узлов; без него на телефоне пользователь после «Next» остаётся внизу новой страницы.

## Прочее

- Денежные значения в тенге (₸) за минуту, пробег в км.
- Даты отображаются через `Intl.DateTimeFormat('en-GB')`.
- «Сервис просрочен» — если с последнего ТО прошло больше 180 дней (`SERVICE_INTERVAL_DAYS`).
- «Низкий уровень топлива/заряда» — меньше 20 %.
- PDF с заданием лежит в корне, но исключён из git через `.gitignore` (`*.pdf`): это материал курса, а не часть приложения, и публиковать его в открытом репозитории не нужно.
- `useSessionState` при чтении объединяет сохранённый объект с значениями по умолчанию: если в `query` добавить новое поле (например, новый фильтр), уже открытая вкладка получит для него значение по умолчанию, и `<select>` не станет uncontrolled.
- Ручная проверка автоматизирована сценарием Playwright (51 проверка: поиск, фильтры, сортировка, пагинация, гонка запросов, empty/error/loading, смена статуса, сохранение/сброс состояния, форма, 404, `?simulateError`, отсутствие горизонтального скролла на 360/768/1280, отсутствие ошибок и предупреждений в консоли). Скрипт запускался вне репозитория, чтобы не добавлять в проект зависимости, не нужные для сдачи.

## Аутентификация (Homework 6)

| Решение | Почему |
| --- | --- |
| Firebase Auth подключён модульным SDK (`firebase/auth`), инициализация — только в `src/firebase.js` | Один файл читает `import.meta.env`; остальной код не знает, откуда взялись ключи. Упрощает замену бэкенда аутентификации. |
| `AuthContext.js` (контекст) и `AuthProvider.jsx` (компонент) — разные файлы, `useAuth` — третий | Правило `react-refresh/only-export-components`: файл с компонентом не должен экспортировать ничего, кроме компонентов, иначе ломается hot reload. |
| `onAuthStateChanged` — единственный источник истины о пользователе | Действия входа/выхода не пишут состояние напрямую: тогда вход в соседней вкладке и восстановление сессии приходят по тому же пути, что и обычный логин. |
| Состояние `loading` отдельно от «не залогинен» | Пока Firebase восстанавливает сессию, пользователь ещё не «анонимный». Без этого различения `ProtectedRoute` выбрасывал бы залогиненного на `/login` при каждой перезагрузке. |
| Коды ошибок Firebase переводятся в сообщения и привязываются к полю формы | `auth/invalid-credential` в интерфейсе бесполезен; плюс отдельные подсказки для ошибок конфигурации (`auth/operation-not-allowed`, `auth/unauthorized-domain`). |
| Приложение работает без ключей Firebase (режим «не настроено») | Проверяющий может запустить `npm run dev` сразу после `git clone`: список машин, фильтры и кэш работают, а баннер объясняет, каких переменных не хватает. |
| Защищены `/profile` и `/vehicles/new`; смена статуса и удаление — видимы, но заблокированы с подсказкой | Публичный просмотр парка полезен и не опасен, а изменять данные должен только диспетчер. Блокировка вместо редиректа не выбрасывает пользователя со страницы, которую он читает. |

## Кэширование серверных данных (Homework 6)

| Решение | Почему |
| --- | --- |
| TanStack Query вместо самописного слоя кэша | Задание разрешает оба варианта. Query keys, `staleTime`/`gcTime`, инвалидация, отмена по `AbortSignal` и `keepPreviousData` — ровно те механизмы, которые требует задание, и они не требуют писать и отлаживать собственный кэш. |
| Все ключи строит одна фабрика `queryKeys.js` | Ключ нигде не пишется строкой дважды; инвалидация адресует целые семейства (`['vehicles','list']`), не перечисляя комбинации фильтров. |
| Параметры запроса входят в ключ | Каждая комбинация фильтров — отдельная запись кэша: возврат к уже просмотренному фильтру или странице происходит мгновенно и без запроса. |
| `staleTime` 60 с (счётчики — 30 с), `gcTime` 5 мин | Парк меняется редко, а ответы API «дорогие» (400–900 мс). Ревалидация — при возвращении в вкладку и при восстановлении сети, но только для устаревших записей. |
| Retry только для 5xx | 404/409/422 — окончательный ответ сервера; повтор лишь тратит время пользователя. |
| Мутации пишут сущность в кэш (`setQueryData`) и инвалидируют списки | Карточка открывается без запроса, а списки и счётчики, на которые мутация могла повлиять, помечаются устаревшими. React Query перезапросит только то, что сейчас на экране. |
| `cancelQueries` перед сменой статуса | Иначе уже летящий GET этой машины приземлится после мутации и вернёт на экран старый статус. |
| Компоненты больше не делают `useEffect` + `fetch` | Эффекты с ручной отменой заменены хуками `use*Query`; состояние загрузки/ошибки/обновления приходит из кэша. Это же выполняет требование «не делать запросы прямо в компонентах». |
